## 1. 프로젝트 개요

- 프로젝트 이름: 오늘 날씨 알리미 (How's the weather)
- 한 줄 소개: 시각장애인이 "오늘 날씨가 뭐야?"라고 말로 물으면, 오늘 날씨를 목소리로 알려주는 앱
- 만드는 사람: MUNHO KANG
- 완성 목표일: 2026-10-05 (인공지능프로그래밍 과제 제출 전)

## 2. 왜 만드나요? (목적)

- 일반 날씨 앱은 아이콘, 그래프, 작은 숫자처럼 **눈으로 보는 정보** 위주라 시각장애인이 쓰기 어렵다.
- 화면 읽기 기능(VoiceOver)으로 일반 날씨 앱을 쓰면 광고, 탭, 시간별 표까지 하나하나 읽어서, 정작 알고 싶은 "오늘 덥나? 우산 챙겨야 하나?"에 도달하기까지 오래 걸린다.
- 그래서 **한 번 묻고, 한 번 들으면 끝나는** 앱이 필요하다. 화면을 보지 않아도 모든 기능을 쓸 수 있어야 한다.

## 3. 누가 사용하나요? (사용자)

- 주 사용자: 시각장애인 (앞이 전혀 보이지 않는 전맹, 조금 보이는 저시력 모두)
- 사용 환경: 주로 아이폰 (VoiceOver를 켜고 사용), 가끔 컴퓨터의 웹 브라우저(Chrome)
- 사용자에 대해 알아야 할 점:
  - 3-1. 화면을 보지 않고 VoiceOver(화면을 읽어주는 기능)로 앱을 조작한다. 모든 버튼과 글에 읽을 수 있는 이름이 있어야 한다.
  - 3-2. 저시력 사용자는 화면을 조금 볼 수 있다. 글씨가 크고 배경과 글자 색 차이(대비)가 뚜렷해야 한다.
  - 3-3. 작은 버튼은 찾기 어렵다. 누를 곳은 크고 적어야 한다.

## 3-1. 대표 사용자 페르소나

- 이름/나이: 김민수 (가상 인물) / 45세, 10년 전 시력을 잃은 전맹
- 상황: 아침 출근 직전 현관에서 "오늘 우산을 챙길까, 겉옷을 입을까"를 결정하려고 쓴다.
- 바라는 것: 앱을 켜고 10초 안에 오늘 기온과 비 소식을 듣는 것
- 불편해하는 것: 메뉴가 많은 앱, 작은 버튼, 쓸데없이 긴 안내, 화면을 봐야만 알 수 있는 정보

## 4. 꼭 있어야 하는 기능 (핵심 기능)

1. **4-1.** 사용자는 화면 대부분을 차지하는 큰 버튼 하나를 눌러 음성 질문을 시작할 수 있다.
2. **4-2.** 사용자는 "오늘 날씨가 뭐야?", "날씨 알려줘"처럼 한국어로 말해서 날씨를 물어볼 수 있다.
3. **4-3.** 사용자는 오늘 날씨(하늘 상태, 현재 기온, 최고·최저 기온, 비 올 확률, 우산 필요 여부)를 목소리로 들을 수 있고, 방금 들은 내용을 다시 들을 수 있다.
4. **4-4.** 사용자는 지금 자기가 있는 위치의 날씨를 들을 수 있다.
5. **4-5.** 사용자는 문제가 생겼을 때(말을 못 알아들음, 인터넷 끊김, 위치 권한 없음) 무엇을 하면 되는지 목소리로 안내받을 수 있다.

## 5. 만들지 않는 것 (범위 제외)

- 5-1. 주간 예보, 시간별 예보 (오늘 날씨만 알려준다)
- 5-2. 회원가입, 로그인
- 5-3. 여러 도시 검색, 즐겨찾는 지역 저장
- 5-4. 정해진 시간에 자동으로 알려주는 알림
- 5-5. 버튼 없이 "헤이 ○○"처럼 항상 귀 기울이는 호출어 기능
- 5-6. 날씨 외의 질문에 대답하는 대화(챗봇) 기능
- 5-7. 안드로이드 버전 (이번에는 iOS와 웹만)
- 5-8. 날씨 그림, 애니메이션, 그래프 같은 눈으로 보는 장식
- 5-9. 미세먼지, 자외선 같은 추가 정보

## 6. 모양과 분위기 (디자인)

- 6-1. 원하는 느낌: 단순함. 화면은 하나, 누를 곳도 하나.
- 6-2. 주요 색상: 고대비. 검은 배경에 노란색·흰색 글씨 (저시력 사용자가 가장 잘 보이는 조합)
- 6-3. 글씨 크기: 본문 최소 28pt 이상
- 6-4. 버튼 크기: 화면 높이의 절반 이상
- 참고: iOS 접근성 가이드(VoiceOver), 웹 접근성 지침(WCAG)의 대비 기준

## 7. 기술 조건

- 7-1. 결과물 형태: Flutter 앱 하나로 iOS 앱과 웹 앱 두 가지 버전
- 7-2. 날씨 정보: Open-Meteo (무료, 가입·API 키 필요 없음)
- 7-3. 음성: 기기에 들어 있는 음성 인식(말 → 글)과 음성 합성(글 → 말) 기능 사용
- 7-4. 접근성: 모든 화면 요소에 VoiceOver가 읽을 이름(라벨)을 붙인다. 앱이 직접 말하는 소리와 VoiceOver 소리가 겹치지 않아야 한다.
- 7-5. 개인정보: 위치나 음성을 저장하거나 외부로 보내지 않는다 (날씨 조회에 필요한 좌표만 날씨 서비스에 보낸다).
- 7-6. 소스 코드 위치: 이 저장소의 `PRD/` 폴더 안

## 8. 가정한 것들

- 8-1. 사용자는 한국어를 쓴다.
- 8-2. 사용자 기기는 인터넷에 연결되어 있다.
- 8-3. 사용자 기기에는 마이크와 스피커가 있다.
- 8-4. 웹 버전은 음성 인식을 지원하는 Chrome 브라우저에서 쓴다고 가정한다.
- 8-5. "오늘"은 사용자가 있는 곳의 시간을 기준으로 한다.

## 9. 결정하거나 조사해야 할 것 (열린 질문)

- 9-1. 위치 권한을 거부했거나 위치를 알 수 없을 때, 어느 지역 날씨를 알려줄까? (예: 서울로 대신 알려주기 / 위치를 켜달라고 안내만 하기)
  - **결정:** 위치를 알 수 없다고 말한 뒤 서울 날씨로 대신 알려준다.
- 9-2. 앱을 켜자마자 바로 듣기 시작할까, 아니면 버튼을 눌러야 듣기 시작할까?
  - **결정:** 버튼을 눌러야 듣기 시작한다. (의도치 않은 녹음 방지, VoiceOver 안내와 겹침 방지)
- 9-3. 날씨를 읽어줄 때 앱의 음성 합성을 쓸까, VoiceOver에게 읽게 할까? (둘이 동시에 말하면 겹친다)
  - **결정:** 앱 음성 합성으로 읽어주고, 화면 글자도 함께 바꾼다. VoiceOver가 같은 내용을 자동으로 또 읽지 않게 한다.
- 9-4. 말하는 속도를 사용자가 조절할 수 있어야 할까?
  - **결정:** 이번에는 조절 기능을 만들지 않고 기본 속도로 고정한다.

## 10. 완성 기준 (이러면 성공!)

- 10-1. iOS 시뮬레이터와 웹(Chrome)에서 앱이 실행된다.
- 10-2. 버튼을 누르고 "오늘 날씨가 뭐야?"라고 말하면 10초 안에 오늘 날씨를 목소리로 들려준다.
- 10-3. 답에 하늘 상태, 현재 기온, 최고·최저 기온, 비 올 확률, 우산 필요 여부가 모두 들어 있다.
- 10-4. 현재 위치 기준 날씨를 알려준다. 위치를 쓸 수 없을 때는 그 사실과 대신 알려주는 지역을 말해준다.
- 10-5. VoiceOver를 켜고 화면을 쓸어 넘기기만 해도 버튼과 날씨 결과를 모두 들을 수 있다.
- 10-6. 인터넷이 끊기거나 말을 못 알아들으면 다음에 무엇을 하면 되는지 목소리로 안내한다.
- 10-7. 저시력 사용자를 위해 글씨는 28pt 이상, 배경과 글자의 대비가 뚜렷하다.
- 10-8. 자동 테스트가 모두 통과한다.
