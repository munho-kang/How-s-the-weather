# 오늘 날씨 알리미 — 구현 Todolist

> 근거 문서: [PRD.md](./PRD.md)
> 모든 할 일에는 "단계-순번" 번호(예: 1-1)가 있고, 괄호 안은 그 할 일이 필요한 PRD 항목 번호입니다.
> 커밋 메시지에도 할 일 번호를 적어 깃허브 기록과 이 문서를 연결합니다. (예: `feat(prd): 고대비 테마 적용 [1-2]`)

## 1단계. 고대비 화면 뼈대

**단계 목표:** iOS와 웹에서 검은 배경에 큰 버튼 하나와 큰 안내 글이 있는 화면이 뜬다.

- [x] **1-1.** `PRD/weather_app` 폴더에 iOS·웹용 Flutter 프로젝트를 만든다 (PRD #7-1, #7-6)
- [x] **1-2.** 검은 배경, 노란색·흰색 글씨의 고대비 테마를 적용한다 (PRD #6-2, #3-2)
- [x] **1-3.** 화면 높이의 절반 이상을 차지하는 "날씨 물어보기" 버튼 하나를 배치한다 (PRD #4-1, #6-4, #3-3)
- [x] **1-4.** 안내·결과 문장을 보여줄 글 영역을 28pt 이상 크기로 배치한다 (PRD #6-3, #3-2)
- [x] **1-5.** 버튼과 글 영역에 VoiceOver가 읽을 이름(라벨)을 붙인다 (PRD #3-1, #7-4)
- [x] **1-6.** 첫 화면에 버튼과 안내 글이 보이는지 확인하는 자동 테스트를 만든다 (PRD #10-8)

**확인 방법**
- iOS 시뮬레이터와 Chrome에서 앱을 열면 검은 화면에 노란 큰 버튼과 큰 흰 글씨가 보인다.
- 버튼이 화면 높이의 절반 이상이다.
- 스크린샷 2장(iOS, 웹)으로 확인할 수 있다.

## 2단계. 오늘 날씨를 문장으로 보여주기

**단계 목표:** 버튼을 누르면 서울의 오늘 날씨가 5가지 정보가 담긴 한 문장으로 화면에 나온다.

- [x] **2-1.** Open-Meteo에서 오늘 날씨(현재 기온, 최고·최저 기온, 비 올 확률, 하늘 상태 코드)를 가져온다 (PRD #7-2, #4-3)
- [x] **2-2.** 하늘 상태 코드를 "맑음", "흐림", "비" 같은 한국어로 바꾼다 (PRD #4-3, #10-3)
- [x] **2-3.** 비 올 확률로 "우산을 챙기세요 / 챙기지 않아도 돼요" 문장을 만든다 (PRD #4-3, #10-3)
- [x] **2-4.** 하늘 상태·현재 기온·최고·최저·비 올 확률·우산 안내를 담은 날씨 문장을 만든다 (PRD #10-3)
- [x] **2-5.** 버튼을 누르면 날씨 문장을 글 영역에 보여준다 (PRD #4-3)
- [x] **2-6.** 날씨 코드 변환, 우산 판단, 문장 만들기 자동 테스트를 만든다 (PRD #10-8)

**확인 방법**
- 버튼을 누르면 화면에 "오늘 서울은 맑음, 현재 14도, 최고 19도 최저 13도, 비 올 확률 10퍼센트. 우산은 챙기지 않아도 돼요." 같은 문장이 나온다.
- 문장에 5가지 정보가 모두 들어 있다.

## 3단계. 날씨를 목소리로 읽어주기

**단계 목표:** 날씨 문장이 화면에 나올 때 한국어 목소리로 읽어주고, 글 영역을 누르면 다시 읽어준다.

- [x] **3-1.** 한국어 음성 합성(TTS)으로 날씨 문장을 읽어준다 (PRD #4-3, #7-3, #9-3)
- [x] **3-2.** 결과 글 영역을 누르면 방금 들은 날씨를 다시 읽어준다 (PRD #4-3)
- [x] **3-3.** 앱이 읽는 동안 VoiceOver가 같은 문장을 자동으로 또 읽지 않게 한다 (PRD #7-4, #9-3)
- [x] **3-4.** 읽어주기·다시 듣기 자동 테스트를 만든다 (PRD #10-8)

**확인 방법**
- 버튼을 누르면 화면 문장과 같은 내용이 목소리로 나온다.
- 결과 글을 누르면 같은 내용을 한 번 더 들을 수 있다.

## 4단계. 목소리로 질문 듣기

**단계 목표:** 버튼을 누르고 "오늘 날씨가 뭐야?"라고 말하면 알아듣고 날씨를 읽어준다.

- [x] **4-1.** 음성 인식(STT)을 추가하고 iOS 마이크·음성 인식 권한 문구를 넣는다 (PRD #4-2, #7-3)
- [x] **4-2.** 버튼을 누르면 "말씀하세요"라고 짧게 안내한 뒤 듣기 시작한다 (PRD #4-1, #9-2)
- [x] **4-3.** "오늘 날씨가 뭐야?", "날씨 알려줘"처럼 "날씨"가 들어간 말을 날씨 질문으로 알아듣는다 (PRD #4-2)
- [x] **4-4.** 아무 말도 없거나 날씨 질문이 아니면 "다시 버튼을 누르고 '오늘 날씨가 뭐야'라고 말해 주세요"라고 안내한다 (PRD #4-5, #10-6)
- [x] **4-5.** 질문 판단과 안내 흐름 자동 테스트를 만든다 (PRD #10-8)

**확인 방법**
- 버튼을 누르고 "오늘 날씨가 뭐야?"라고 말하면 날씨를 목소리로 들려준다.
- "지금 몇 시야?"라고 말하면 다시 물어보라는 안내가 나온다.

## 5단계. 현재 위치와 문제 상황 안내

**단계 목표:** 내가 있는 곳의 날씨를 알려주고, 문제가 생기면 무엇을 하면 되는지 목소리로 안내한다.

- [x] **5-1.** 현재 위치를 가져와 그 위치의 날씨를 조회한다. iOS 위치 권한 문구를 넣는다 (PRD #4-4)
- [x] **5-2.** 위치를 알 수 없으면 "위치를 알 수 없어 서울 날씨를 알려드려요"라고 말하고 서울 날씨를 알려준다 (PRD #9-1, #10-4)
- [x] **5-3.** 인터넷이 끊겨 날씨를 못 가져오면 "인터넷 연결을 확인하고 다시 눌러 주세요"라고 안내한다 (PRD #4-5, #10-6)
- [x] **5-4.** 마이크·음성 인식 권한이 없으면 권한을 켜는 방법을 안내한다 (PRD #4-5)
- [x] **5-5.** 날씨 조회가 오래 걸리면 끊고 안내해서 10초 안에 답하게 한다 (PRD #10-2)
- [x] **5-6.** 위치 대체, 인터넷 오류, 권한 오류 안내 자동 테스트를 만든다 (PRD #10-8)

**확인 방법**
- 위치 권한을 허용하면 현재 위치 날씨, 거부하면 서울 날씨와 그 이유를 들려준다.
- 인터넷을 끄고 버튼을 누르면 인터넷 확인 안내가 나온다.

## 6단계. 완성 기준 점검 (PRD #10)

**단계 목표:** PRD의 완성 기준 8가지를 하나씩 확인하고 결과를 기록한다.

- [x] **6-1.** iOS 시뮬레이터와 웹(Chrome)에서 앱이 실행된다 (PRD #10-1)
  - 통과: iPhone 17 시뮬레이터 실행·스크린샷, Chrome에서 실행 확인
- [x] **6-2.** 버튼을 누르고 "오늘 날씨가 뭐야?"라고 말하면 10초 안에 목소리로 답한다 (PRD #10-2)
  - 통과: 사용자가 Chrome에서 직접 말해 답을 들음. 최악의 경우 계산이 11초였어서 시간 제한을 줄여 9초로 수정 (`fix(prd)` 커밋)
- [x] **6-3.** 답에 하늘 상태, 현재 기온, 최고·최저 기온, 비 올 확률, 우산 필요 여부가 모두 들어 있다 (PRD #10-3)
  - 통과: `weather_test.dart` 문장 테스트, Chrome에서 실제 날씨 문장 확인
- [x] **6-4.** 현재 위치 날씨를 알려주고, 위치를 못 쓰면 이유와 대신 알려주는 지역(서울)을 말한다 (PRD #10-4)
  - 자동 테스트 통과(`problems_test.dart`). **사람 확인 완료:** 실제 위치 허용/거부 시 답 확인
- [x] **6-5.** VoiceOver를 켜고 쓸어 넘기기만 해도 버튼과 결과를 모두 들을 수 있다 (PRD #10-5)
  - 자동 테스트 통과(`completion_test.dart`: 안내 글 → 버튼 순서, 이름·사용법 안내 있음). **사람 확인 완료:** VoiceOver로 실제 확인
- [x] **6-6.** 인터넷이 끊기거나 말을 못 알아들으면 다음 행동을 목소리로 안내한다 (PRD #10-6)
  - 통과: `problems_test.dart`, `listen_test.dart`, 사용자가 "지금 몇 시야"로 안내 확인
- [x] **6-7.** 글씨가 28pt 이상이고 배경과 글자 대비가 뚜렷하다 (PRD #10-7)
  - 통과: 모든 글씨 30pt 이상, 대비율 흰 글씨/검은 배경 21:1, 검은 글씨/노란 버튼 약 15:1 (WCAG 최고 등급 7:1 이상)
- [x] **6-8.** 자동 테스트가 모두 통과한다 (PRD #10-8)
  - 통과: `flutter test` 29개 전부 통과

**확인 방법**
- 각 항목 옆에 확인 결과(통과/실패, 확인한 방법)를 적는다.

<summary>이 Todolist를 만들 때 사용한 프롬프트</summary>

당신은 이 프로젝트의 개발 담당자입니다. 위의 PRD(제품 요구 사항 문서)를 바탕으로, 구현을 위한 todo 리스트를 작성해 주세요. 아직 코드는 작성하지 마세요. 지금은 계획만 세우는 단계입니다.

todo 리스트는 다음 규칙을 지켜서 만들어 주세요.

1. 전체 작업을 4~6개의 단계로 나누세요. 각 단계는 끝났을 때 눈으로 확인할 수 있는 결과물이 있어야 합니다. 화면에 보이는 것을 먼저, 세부 기능은 나중에 배치하세요.

2. 각 단계마다 다음을 포함하세요.
- 단계 목표: 이 단계가 끝나면 무엇이 되는지 한 문장으로
- 할 일 목록: 체크박스 형태로, 하나의 할 일은 하나의 작업만 담을 것
- 할 일 번호: 모든 할 일에 "단계-순번" 형식의 번호를 붙일 것 (예: 1-1, 1-2, 2-1). 이후 대화에서 저와 당신 모두 이 번호로 작업을 지목합니다.
- 확인 방법: 내가 직접 눈으로 검사할 수 있는 기준

3. 모든 할 일 옆에 PRD의 어떤 항목 때문에 필요한 작업인지 번호를 표시하세요. 예: (PRD #4-1). PRD에 근거가 없는 할 일은 넣지 말고, 꼭 필요하다고 판단되면 별도로 "추가 제안" 섹션에 분리해서 이유와 함께 제안하세요.

4. PRD의 "만들지 않는 것" 항목을 리스트 마지막에 "하지 않기로 한 것"으로 다시 정리하고, "제외-1, 제외-2" 형식으로 번호를 붙이세요. 작업 중에 이 항목을 구현하자고 제안하지 마세요.

5. 마지막 단계는 반드시 PRD의 "완성 기준"을 하나씩 점검하는 체크리스트로 만드세요.

6. PRD의 "열린 질문" 항목 중 계획 수립에 영향을 주는 것이 있다면, todo 리스트를 만들기 전에 먼저 저에게 질문하세요.

todo 리스트를 제안한 뒤에는 제 승인을 기다리세요. 승인 전에는 구현을 시작하지 마세요. 승인 후에는 한 단계가 끝날 때마다 완료한 할 일 번호를 나열하며 결과를 보고하고(예: "1-1부터 1-4까지 완료했습니다"), 제가 확인한 다음에 다음 단계로 넘어가세요.
